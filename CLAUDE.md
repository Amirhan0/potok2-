# CLAUDE.md

Одностраничный лендинг магазина одежды: формы заявок и подписки, собственные SVG-иллюстрации, сине-коралловая палитра. Главные требования: страница быстро загружается, хорошо выглядит и работает с клавиатуры и экранного диктора.

## Стек

| Задача        | Инструмент                                                         | Почему                                     |
| ------------- | ------------------------------------------------------------------ | ------------------------------------------ |
| Фреймворк     | **Astro 5** (`output: 'static'`)                                   | По умолчанию на клиент уходит 0 KB JS      |
| Стили         | **Tailwind CSS v4** (`@tailwindcss/vite`)                          | Токены в `@theme`, без `tailwind.config`   |
| Язык          | **TypeScript** (strict)                                            |                                            |
| Интерактив    | Чистый TS в `<script>` компонентов Astro                           | Без React/Vue, если без них можно обойтись |
| Шрифты        | `@fontsource-variable/*`, локально                                 | Без запросов к Google Fonts                |
| Изображения   | `astro:assets` (`<Image>` / `<Picture>`) → AVIF/WebP               |                                            |
| Отправка форм | Внешний эндпоинт из `PUBLIC_FORM_ENDPOINT` (Formspree / Web3Forms) | Своего бэкенда нет                         |
| Линт/формат   | Prettier + `prettier-plugin-astro`, `astro check`                  |                                            |

Новые зависимости добавляй только если без них правда никак. Перед установкой проверь, что ту же задачу нельзя решить нативным HTML/CSS: `<details>` для FAQ, `<dialog>` для модалок, CSS scroll-snap для каруселей, `IntersectionObserver` для анимаций при скролле.

## Команды

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # сборка в dist/
npm run preview    # просмотр собранной версии
npm run check      # astro check (типы и шаблоны)
npm run format     # prettier --write .
```

Перед тем как сказать, что задача готова, запусти `npm run check` и `npm run build`. Оба должны пройти без ошибок.

## Структура

```
src/
  pages/index.astro          # единственная страница, собирает секции по порядку
  layouts/Base.astro         # <head>, meta, OG-теги, шрифты, подключение global.css
  components/
    sections/                # Hero, Collection, Benefits, Lookbook, Consult, Reviews, Subscribe, Faq, Footer
    ui/                      # Button, Input, Select, Field, Badge, Card
    illustrations/           # SVG-иллюстрации как Astro-компоненты
  scripts/forms.ts           # общая логика валидации и отправки форм
  styles/global.css          # @import "tailwindcss"; @theme { ... }
  data/                      # products.ts, reviews.ts, faq.ts: контент отдельно от разметки
public/                      # favicon.svg, og-image.png, robots.txt
```

Контент (товары, отзывы, FAQ) лежит в `src/data/*.ts` с типами. Тексты не хардкодь прямо в разметке секций.

## Дизайн-система

### Палитра: синий и коралловый

Синий отвечает за доверие и спокойствие, тёплый коралловый даёт контраст и «модный» акцент, а кремовый фон смягчает холодный синий.

```css
/* src/styles/global.css */
@theme {
  --color-navy-900: #0b1f4d; /* основной текст, футер, тёмные секции */
  --color-blue-700: #1e40af; /* заголовки, ссылки при наведении */
  --color-blue-600: #2563eb; /* основной бренд-цвет, primary-кнопки */
  --color-blue-400: #60a5fa; /* обводки, иконки, элементы иллюстраций */
  --color-blue-100: #dbeafe; /* фоны карточек и плашек */
  --color-coral-500: #ff7a59; /* акцент: CTA, бейджи «New», «Sale» */
  --color-coral-300: #ffb49e; /* мягкий акцент в иллюстрациях */
  --color-cream-50: #fff8f1; /* основной фон страницы */
  --color-ink-500: #475569; /* второстепенный текст */
  --color-error-600: #c2410c; /* текст ошибок валидации (coral-500 не проходит по контрасту) */

  --font-display: "Unbounded Variable", system-ui, sans-serif;
  --font-sans: "Manrope Variable", system-ui, sans-serif;

  --radius-card: 1.5rem;
}
```

Правила использования цветов:

- Фон страницы `cream-50`. Тёмные секции (футер, блок подписки) делай на `navy-900` со светлым текстом.
- Основная кнопка: `blue-600` с белым текстом. Акцентная CTA: `coral-500` с текстом **`navy-900`**, потому что белый на коралловом не проходит по контрасту WCAG AA.
- Коралловым **не набирай** основной текст на светлом фоне, он годится только для заливок и декора.
- На одном экране должно быть не больше одного кораллового CTA, иначе акцент теряется.
- Цвета бери только из токенов (`bg-blue-600`, `text-navy-900`). Произвольные hex в классах (`bg-[#123456]`) не используй.

### Тёмная тема

Тема задаётся атрибутом `data-theme="light|dark"` на `<html>`. Начальное значение ставит inline-скрипт в `Base.astro` до отрисовки: сохранённый выбор из `localStorage.theme`, иначе системная настройка. Переключатель — `ui/ThemeToggle.astro`.

Для всего, что зависит от темы, используй **семантические токены**. Их значения переопределяются в `[data-theme="dark"]` в `global.css`:

| Токен     | Для чего                                | Вместо      |
| --------- | --------------------------------------- | ----------- |
| `page`    | фон страницы, карточки внутри `surface` | `cream-50`  |
| `surface` | карточки, светлые секции                | `white`     |
| `field`   | фон полей ввода                         | `white`     |
| `fg`      | основной текст                          | `navy-900`  |
| `muted`   | второстепенный текст                    | `ink-500`   |
| `line`    | рамки, разделители                      | `blue-100`  |
| `tint`    | плашки, фон иллюстраций                 | `blue-100`  |
| `link`    | ссылки, цены, акцентный текст           | `blue-700`  |
| `error`   | текст ошибок                            | `error-600` |
| `band`    | яркая синяя секция                      | `blue-700`  |
| `outline` | контуры SVG (`var(--color-outline)`)    | `navy-900`  |

- Палитру (`navy-900`, `coral-500`, `blue-600`…) используй напрямую только там, где цвет не должен меняться: кнопки, бейджи, тёмные секции (`bg-navy-900` + `text-white`), текст на коралловом.
- Точечные правки делай вариантом `dark:` (например, `dark:bg-blue-600`), но сначала проверь, нельзя ли обойтись семантическим токеном.
- Новую секцию или компонент проверяй в обеих темах.
- Не вешай `hidden` на `<Button>`: его базовый `inline-flex` перебивает `hidden`. Скрывай обёртку.

### Типографика и ритм

- Заголовки пишутся `font-display`, текст `font-sans`. Для заголовков используй `clamp()` (`text-[clamp(2.5rem,6vw,4.5rem)]`).
- Вертикальный отступ секций: `py-20 md:py-28`. Контейнер: `mx-auto max-w-7xl px-5 md:px-8`.
- Карточки: `rounded-card` (из токена `--radius-card`), тени лёгкие, по возможности с синим оттенком (`shadow-blue-900/10`).

### Иллюстрации

- Иллюстрации — **собственные inline SVG** в `src/components/illustrations/`: силуэты одежды на вешалках, сложенные свитера, абстрактные «тканевые» волны и пятна (blob), линии строчки (`stroke-dasharray`), звёздочки-блики.
- В SVG используй только цвета палитры, через `currentColor` или CSS-переменные (`fill="var(--color-blue-400)"`). Так одну иллюстрацию можно перекрасить классом.
- У каждой SVG должен быть `viewBox`, но не должно быть фиксированных `width`/`height`. Размер задаётся классами. Декоративные SVG помечай `aria-hidden="true"`, смысловые — `role="img"` с `<title>`.
- Анимации только через CSS (`transform`, `opacity`): мягкое «покачивание» вешалок, плавающие blob-ы. Обязательно оборачивай их в `@media (prefers-reduced-motion: no-preference)`.
- Растровые фото товаров кладутся в `src/assets/` и выводятся только через `<Image>`/`<Picture>` с `alt`, `width`, `height` и `loading="lazy"`. Исключение — hero-изображение, у него `loading="eager"` и `fetchpriority="high"`.

## Формы

На странице три формы. Все они используют общую логику из `src/scripts/forms.ts`.

1. **Hero / «Подобрать образ»**: имя, телефон или Telegram, стиль (select: casual / office / вечерний / спорт).
2. **Консультация стилиста / подбор размера**: имя, телефон, рост, обхват груди/талии/бёдер (необязательные), комментарий, чекбокс согласия на обработку ПДн.
3. **Подписка на новинки**: email и чекбокс согласия.

Требования:

- Форма сначала работает на чистом HTML: `<form action={endpoint} method="POST">`, атрибуты `required`, `type="email"`, `type="tel"`, `inputmode`, `autocomplete` (`name`, `tel`, `email`). JS только улучшает поведение: отправка через `fetch` без перезагрузки, состояния и сообщения.
- У каждого поля есть видимый `<label for>`. Placeholder не заменяет label.
- Ошибки показываются под полем, связаны через `aria-describedby` и помечают поле `aria-invalid="true"`. Проверка срабатывает на `blur` и `submit`, а не на каждое нажатие клавиши.
- У формы четыре состояния: `idle` → `submitting` (кнопка `disabled` со спиннером) → `success` (сообщение в `role="status"`, форма очищается) / `error` (сообщение и возможность повторить).
- Против спама: скрытое поле-ловушка `name="website"`. Если оно заполнено, отправку тихо отменяем.
- Телефон маскируется без библиотек: простая нормализация к `+7 (XXX) XXX-XX-XX` в `forms.ts`.
- Адрес эндпоинта берётся из `import.meta.env.PUBLIC_FORM_ENDPOINT`. Пример значения лежит в `.env.example`, сам `.env` не коммитится.
- Тексты ошибок пишутся на русском и по-человечески («Проверьте номер — не хватает цифр»).

## Производительность (бюджет)

- JS на клиенте: **≤ 15 KB gzip** в сумме.
- CSS: **≤ 25 KB gzip**.
- Lighthouse (mobile): Performance ≥ 95, Accessibility = 100, Best Practices ≥ 95, SEO = 100.
- LCP < 2.0 s, CLS < 0.05. У всех медиа заданы размеры, шрифты подключены с `font-display: swap`, основной шрифт предзагружается.
- Сторонние скрипты (аналитика, чаты) не подключай без явной просьбы.

## Доступность и SEO

- Семантика: один `<h1>` в hero, у секций `<section aria-labelledby>`, навигация в `<nav>`, есть ссылка «Перейти к содержимому».
- Фокус всегда виден: `focus-visible:outline-2 outline-offset-2 outline-blue-600`.
- Страница корректно выглядит от 360 px до 1440 px и шире. Вёрстка mobile-first.
- В `Base.astro` есть `lang="ru"`, `title`, `description`, OG/Twitter-теги, `theme-color` (`#2563EB`), канонический URL, а также JSON-LD `ClothingStore`.

## Стиль кода

- Компоненты Astro называются в PascalCase, по одному компоненту на файл. Пропсы описываются через `interface Props`.
- Утилиты Tailwind пиши прямо в разметке. `@apply` допустим только в `global.css` для базовых стилей форм.
- Не дублируй разметку кнопок и полей, бери компоненты из `ui/`.
- Комментарии в коде пишутся на русском и только там, где без них неочевидно.
- Коммиты пишутся на русском, в повелительном наклонении: «Добавить секцию отзывов».

## Чего не делать

- Не подключать React/Vue/Svelte, jQuery, анимационные библиотеки (GSAP, Framer Motion) и UI-киты без явной просьбы.
- Не использовать стоковые иллюстрации и внешние CDN для картинок и шрифтов.
- Не ставить огромные фоновые видео и PNG вместо SVG.
- Не коммитить `.env`, `dist/` и `node_modules/`.
